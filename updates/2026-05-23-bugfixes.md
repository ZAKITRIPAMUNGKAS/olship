# Update Log - 23 Mei 2026 (Bug Fixes & Security)

Log ini mencatat detail perbaikan bug kritis (P0 & P1) yang diterapkan pada sistem e-commerce **Listrindo Jaya Elektrik** (folder `OLSHOP FIX`).

---

## 📋 Ringkasan Pembaruan

| Tingkat Keparahan | Komponen | Deskripsi Masalah | Solusi & Tindakan |
| :--- | :--- | :--- | :--- |
| **P0 (Kritis)** | Routing | Rute callback `/payment/callback` terhalang middleware `auth`. | Dipindahkan ke rute publik di luar grup `auth` agar server Midtrans dapat mengirim callback status secara langsung. |
| **P0 (Kritis)** | Webhook | Nilai status tidak valid di-update ke DB (seperti `'pending'`, `'denied'`) sehingga memicu crash MySQL strict mode. | Dilakukan pemetaan status webhook Midtrans secara ketat ke enum kolom `payment_status` DB (`unpaid`, `paid`, `failed`, `expired`). |
| **P0 (Kritis)** | Webhook / Stok | Stok produk tidak dikembalikan jika transaksi dibatalkan atau kedaluwarsa. | Implementasi pemulihan stok produk secara transaksional (`restoreStock`) ketika status berubah menjadi `cancel` atau `expire`. |
| **P0 (Kritis)** | Webhook / Log | Transaksi tidak tercatat di tabel `payments`. | Ditambahkan pencatatan detail respons pembayaran ke tabel `payments` (termasuk penyimpanan raw payload di kolom `meta`). |
| **P0 (Kritis)** | Background Job | Job `SyncPendingPayments` memanggil method yang tidak ada pada `PaymentService`. | Diimplementasikan method `syncPaymentStatus` di `PaymentService` untuk sinkronisasi otomatis status order via API status Midtrans. |
| **P1 (Tinggi)** | Admin Controller | Missing import facade `DB` pada `Admin\OrderController`, memicu runtime crash saat admin melakukan refund. | Menambahkan `use Illuminate\Support\Facades\DB;` di baris atas file controller. |
| **P2 (Medium)** | Testing | `ExampleTest` memicu crash "no such table: products" karena database in-memory tidak dimigrasi. | Mengaktifkan trait `RefreshDatabase` pada `ExampleTest` sehingga database otomatis dimigrasi sebelum pengujian dijalankan. |
